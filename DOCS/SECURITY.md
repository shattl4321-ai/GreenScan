# Безопасность GreenScan

## API keys

- Все ключи задаются через **переменные окружения** (файл `BACKEND/.env`).
- Ключи **не должны** попадать в Git, документацию или логи.

`BACKEND/.gitignore` исключает `.env`.

## Ошибки пользователю

- Пользователю возвращаются **общие** сообщения (`detail`), без технических деталей провайдера.
- Технические ошибки пишутся в лог через `_log_provider_error`.
- API-ключ OpenAI маскируется в логах (`replace(api_key, "***")`).

## Логи

- Логи: `BACKEND/logs/greenscan.log` + консоль.
- Сообщения об ошибках провайдера обрезаются до 400 символов.
- Секреты не должны попадать в логи намеренно; при ошибках OpenRouter ключ также маскируется.

## Пользовательские изображения

- Изображения передаются во **внешний Vision API** (OpenAI, Google, OpenRouter) в формате base64.
- GreenScan **не сохраняет** загруженные изображения на диск (в текущей реализации `main.py`).
- Изображения не пишутся в логи.

## CORS

Текущая конфигурация: `allow_origins=["*"]`. Для production рекомендуется ограничить origins — **не реализовано** в текущей версии.

## HTTPS

Локальная разработка использует HTTP. TLS для production **не настроен**.

## Аутентификация

API **не требует** аутентификации. Любой клиент, знающий URL, может отправить запрос.

## Rate limiting

Ограничение частоты запросов **не реализовано**.

## Размер файлов

Ограничение размера загружаемых файлов в backend и frontend **не задано**.

## Хранение данных

База данных **отсутствует**. История анализов не сохраняется.

## .env в Git

Перед коммитом убедитесь, что `.env` не попал в индекс Git. Проверьте `git status`.

Корневой `.gitignore` **отсутствует** — только `BACKEND/.gitignore`.
