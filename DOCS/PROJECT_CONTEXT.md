# GreenScan — Project Context

## 1. Название

GreenScan.

## 2. Идея

Пользователь загружает несколько фотографий газона. Приложение анализирует визуальные признаки и предлагает рекомендации по уходу.

## 3. Цель MVP

Проект выполняется как **учебная / portfolio работа** (курсовой MVP).

Целевая аудитория: владельцы частных домов и дач. Основной контекст использования — **Россия** (рекомендации и база знаний ориентированы на распространённые средства ухода, доступные на российском рынке).

Создать рабочий прототип, который:

- принимает 2–5 фотографий;
- проверяет, что на снимках газон;
- извлекает визуальные признаки через Vision AI;
- формирует рекомендации на основе правил и базы знаний.

GreenScan **не заменяет** агронома или профессиональную диагностику.

## 4. Пользовательский сценарий

1. Пользователь открывает `index.html` в браузере (через локальный HTTP-сервер).
2. Загружает от 2 до 5 фотографий газона (drag-and-drop или выбор файлов).
3. Нажимает «Анализировать».
4. Frontend отправляет `POST /analyze-photo` с полем `files` (multipart).
5. Backend для каждого фото вызывает выбранный Vision-провайдер.
6. Ответы Vision валидируются (`validate_vision_results`).
7. Результаты агрегируются (`aggregate_results`).
8. `RuleEngine.evaluate` формирует список действий.
9. `RuleEngine.enrich` обогащает действия данными из KnowledgeBase.
10. Frontend показывает диагноз, уверенность и рекомендации.

## 5. Основные компоненты

| Компонент | Файлы | Роль |
|-----------|-------|------|
| Frontend | `index.html`, `FRONTEND/app.js`, `FRONTEND/styles.css` | UI |
| Backend API | `BACKEND/main.py` | HTTP, Vision, валидация, агрегация |
| Vision | `BACKEND/vision/` | Извлечение признаков из фото |
| RuleEngine | `BACKEND/engine.py` | Правила → действия |
| KnowledgeBase | `BACKEND/knowledge.py`, `BACKEND/knowledge/*.json` | Тексты и подбор продуктов |

## 6. Основные продуктовые решения

### Работа с несколькими фотографиями

- Минимум: **2** фото.
- Максимум: **5** фото.
- Каждое фото анализируется отдельно, затем результаты агрегируются.

### Не-газон

Если хотя бы одно изображение имеет `is_lawn = false`, **весь набор отклоняется**. Хорошие фото отдельно не анализируются.

### Недостоверный Vision-ответ

- `is_lawn` обязателен и должен быть `bool`.
- Отсутствие или некорректный тип → HTTP 422, анализ не продолжается.

### Confidence

- На этапе валидации: если `max(confidence)` по всем фото `<= 0` → HTTP 422.
- При агрегации: `confidence` берётся из **первого** фото (`values[0]`), не через `max` / `min` / `avg`.
- Отдельного числового порога (например 0.2) в коде **нет**.

### Разделение ответственности

- **Vision** отвечает: что видно на фото.
- **RuleEngine** отвечает: какие действия предложить.
- Vision **не формирует** агрономические рекомендации напрямую.

## 7. Что намеренно НЕ входит в MVP

- База данных и хранение истории анализов.
- Аутентификация и личные кабинеты.
- Admin panel.
- Автоматический fallback OpenAI → Gemini → Qwen.
- Production deployment (Docker, Nginx) — не завершён.
- Dedicated health endpoint (`/health`).
- Сохранение загруженных изображений на сервере.
- `requirements.txt` в репозитории.
- Ввод даты фотографий пользователем.
- Видеоанализ.
- Интеграция с погодой.
- GPS / карта участка.
- PWA и мобильное приложение.
- Push-уведомления.
- Маркетплейс удобрений.
- AI-чат / ассистент «что делать с газоном?».
