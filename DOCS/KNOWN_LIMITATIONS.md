# Известные ограничения GreenScan (MVP)

## Анализ

- Анализ основан **только на визуальных признаках** с фотографий.
- GreenScan **не заменяет** профессиональную агрономическую диагностику.
- Состояние почвы, корней, скрытые болезни без визуальных признаков надёжно определить нельзя.
- `soil_issue` в Vision prompt всегда `null` — почвенные проблемы не диагностируются.

## Vision AI

- Качество результата зависит от выбранного провайдера и модели.
- Разные модели могут давать разные результаты на одних и тех же фото.
- Один и тот же участок при повторном анализе может давать различающиеся результаты (нестабильность Vision AI).
- Google периодически выводит старые модели из OpenAI-compatible endpoint; имя модели Gemini может потребовать обновления в `gemini_provider.py`.
- Доступность конкретных model ID на OpenRouter (особенно free-tier) может меняться.
- Модель может ошибочно классифицировать не-газон как газон и наоборот.
- `confidence` зависит от AI-модели; отдельного порога (0.2 / 0.5) в коде нет — отклоняется только `<= 0`.
- Gemini всегда отправляет изображения как JPEG, игнорируя реальный MIME.

## Провайдеры

- **Автоматический fallback** между OpenAI / Gemini / Qwen **отсутствует**.
- При ошибке провайдера пользователь получает HTTP 503 без переключения на другой провайдер.

## RuleEngine

- Часть правил в `expert_rules.json` ссылается на признаки, которых **нет** в Vision-схеме:
  - `excess_moisture`, `spring`, `slow_growth`, `soil_compaction`, `thatch_layer`, `moss`, `shade`, `heat_stress`
- Эти правила в текущем MVP **фактически не срабатывают**.
- Правило `rule_moss` использует condition `moss`, Vision возвращает `moss_presence` — **несовпадение имён**.
- В `expert_rules.json` остаётся action `apply_herbicide` (в `rule_weeds_present`), но runtime пропускает его — вместо этого работает умная логика `spot_weed_control` / `full_weed_control`.
- `fungicides.json` пуст и не загружается — `apply_fungicide` не обогащается продуктами.
- Разные типы грибковых признаков не различаются — все `fungal_signs = true` ведут к одному action `apply_fungicide`.

## Агрегация

- Булевые признаки агрегируются через `any()` — достаточно одного фото.
- `confidence` берётся из **первого** фото, не отражает минимальную уверенность по набору.
- `weed_density` агрегируется через максимум (`low < medium < high`).

## Frontend

- `API_URL` захардкожен: `http://127.0.0.1:8001/analyze-photo`.
- Нет ограничения размера файла на клиенте.
- Нет offline-режима.

## Инфраструктура

- Нет `requirements.txt`.
- Нет Docker-конфигурации.
- Нет health endpoint.
- Нет аутентификации.
- Нет rate limiting.
- Production deployment не завершён.
- Корневой `.gitignore` отсутствует.

## Тестирование

- Нет e2e-тестов frontend.
- Нет интеграционных тестов с реальными Vision API.
- Количество тестов может меняться — не фиксировать как константу.

## Данные

- История анализов не сохраняется.
- Изображения не хранятся на сервере, но передаются внешним API.
