# AI Role — правила для AI-агента GreenScan

Инструкция для AI-разработчика, работающего над проектом GreenScan.

## Роль

Работать как **аккуратный помощник** по существующему MVP. Не переписывать проект целиком.

## Главный принцип

**Не усложнять архитектуру без необходимости.** Минимальный diff, решающий конкретную задачу.

## Перед изменениями

AI обязан:

1. Изучить существующий код (особенно затрагиваемые модули).
2. Определить границы задачи — что входит и что **не** входит.
3. Понять, какие модули затрагиваются: `main.py`, `vision/`, `engine.py`, `knowledge.py`, frontend.
4. Проверить существующие тесты (`test_engine.py`, `test_analyze_photo.py`).
5. Вносить **минимальные** изменения.

## Запрещено без прямого задания

- Большой рефакторинг.
- Смена framework (FastAPI → Flask и т.п.).
- Смена архитектуры.
- Добавление БД.
- Добавление authentication.
- Личные кабинеты.
- Переписывание frontend.
- Новые AI-провайдеры.
- Изменение RuleEngine.
- Изменение KnowledgeBase.
- Изменение Vision prompts (`vision/prompts.py`).
- Изменение deployment / Docker.
- Автоматический fallback между провайдерами.
- «Улучшения заодно» вне scope задачи.

## Продуктовые правила (не нарушать)

- 2–5 фото на запрос.
- `is_lawn = false` у любого фото → отклонить весь набор.
- `is_lawn` обязателен (bool).
- `confidence <= 0` у всех → отклонить анализ.
- Валидация **до** `aggregate_results` и RuleEngine.
- Vision не формирует рекомендации.

## После изменения

AI обязан:

1. Запустить relevant tests (`pytest`).
2. По возможности — полный pytest suite.
3. Перечислить изменённые файлы.
4. Объяснить, что и зачем изменено.
5. Указать риски и спорные места.

## Принцип достоверности

**Не утверждать**, что код делает что-либо, не проверив его.

Если информация не определена из кода — писать: «Не определено в текущей версии проекта.»

## Типичные ошибки (из опыта)

- Запуск uvicorn из корня вместо `BACKEND/` → `Could not import module "main"`.
- Запуск frontend из `FRONTEND/` вместо корня → нет `index.html`.
- Агрегация `is_lawn` через `any()` вместо `all()` → плохое фото теряется.
- Трактовка отсутствия `is_lawn` как `true` → ложный «идеальный газон».
